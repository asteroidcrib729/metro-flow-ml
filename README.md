# Smart Traffic Management System

ML-based hourly traffic volume prediction, interactive geospatial congestion
visualization, and FastAPI REST inference for **I-94 Westbound
(Minneapolis-St. Paul, MN)** using **XGBoost**, **Folium**, `ipywidgets`, and
**FastAPI**.

## Dataset

- **Raw File:** `dataset/Metro_Interstate_Traffic_Volume.csv` (`48,204` rows,
  `9` columns, `2012-10-02 09:00:00` to `2018-09-30 23:00:00`)
- **Cleaned File:** `dataset/traffic_data_cleaned.csv` (`48,187` rows, `12`
  columns after removing `17` exact duplicates and engineering temporal/weather
  features)
- **Source:**
  [UCI Metro Interstate Traffic Volume](https://archive.ics.uci.edu/dataset/492/metro+interstate+traffic+volume)

### Key Fields

- **Weather & Atmospheric:** `temp` (Kelvin), `rain_1h`, `snow_1h`,
  `clouds_all`, `weather_main` (encoded as `weather_code` `0-10`),
  `weather_description`
- **Temporal & Holiday Flags:** `date_time` (expanded into `hour`, `month`,
  `day_of_week`, `year`, `is_weekend`), `holiday` (encoded as `is_holiday`:
  `48,126` non-holiday / `61` holiday rows)
- **Target:** `traffic_volume` (hourly vehicle count along I-94 Westbound)

## Project Structure

- `metro-flow-ml.ipynb` - Unified end-to-end notebook covering:
  1. **Data Preparation & EDA** - `keep_default_na=False` CSV loading
     (preserving literal `"None"` holiday strings), deduplication (`17`
     duplicates removed), explicit timestamp parsing, distribution & rush-hour
     visualizations, deterministic `LabelEncoder` weather mapping, and export to
     `dataset/traffic_data_cleaned.csv`.
  2. **Model Training & Evaluation** - `XGBRegressor` training (`80/20` split,
     `random_state=42`), evaluation ($R^2 = 96.54\%$, $\text{RMSE} = 372$
     vehicles, $\text{MAE} = 218$ vehicles), and serialization to
     `model/traffic_xgboost_model.pkl`.
  3. **Interactive Congestion Dashboard** - `ipywidgets` controls (`Hour`,
     `Day`, `Weather`) paired with a Folium corridor marker and heatmap view
     exported to `visualizations/traffic_map_view.html` using `Esri.WorldTopoMap`
     tiles and `280px` popups.
  4. **FastAPI Prediction Service** - Typed `POST /api/predict-traffic` REST
     endpoint (`TrafficPredictionRequest`) serving predictions from
     `model/traffic_xgboost_model.pkl`.
- `dataset/`
  - `Metro_Interstate_Traffic_Volume.csv` - Raw hourly traffic & weather dataset
  - `traffic_data_cleaned.csv` - Cleaned feature table generated by Phase 1
- `model/`
  - `traffic_xgboost_model.pkl` - Serialized `XGBRegressor` model
- `visualizations/`
  - `traffic_map_view.html` - Exported interactive Folium congestion map
- `tests/`
  - `test_project.py` - Automated validation tests for configuration files,
    notebook compilation/outputs, dataset invariants, serialized model
    inference, and map deliverables
- `.vscode/`
  - `settings.json` - Dedicated VS Code / Antigravity workspace configuration
    for global Python `3.14.7`, Jupyter kernel filtering, Ruff, and Pyrefly
  - `extensions.json` - Recommended editor extensions
- `.github/workflows/ci.yml` - GitHub Actions workflow running Ruff, Pyrefly,
  and unit tests on Python `3.14`
- `.python-version`, `pyproject.toml`, `pyrefly.toml`, `requirements.txt` -
  Python version pinning, project metadata, Pyrefly configuration, and frozen
  dependencies with flexible version ranges

## Complete Setup & Configuration Guide

### 1. Python 3.14.7 Configuration

This project targets **Python 3.14.7** and is pre-configured to connect directly
to the global Python `3.14.7` distribution:

- **`.python-version`**: Pins `3.14.7` so Python environment managers and IDEs
  automatically detect the target interpreter version.
- **`pyproject.toml`**: Declares `requires-python = ">=3.14.7,<3.15"`, core
  runtime dependencies, and typing stub dependencies (`pandas-stubs`,
  `types-seaborn`).
- **`requirements.txt`**: Contains the frozen project dependency set (core
  libraries, Jupyter execution packages, typing stubs, and transitive
  dependencies) using flexible version bounds (e.g., `>=3.4.1,<4.0.0` for
  SemVer packages and `>=` lower bounds for CalVer packages) rather than rigid
  `==` pins.

Verify your active Python installation before installing dependencies:

```bash
python --version
# Expected: Python 3.14.7
```

> **Windows Note:** If multiple Python versions are installed, verify that
> `py -0p` lists `3.14` as active or invoke `py -3.14 -m pip ...` explicitly.

Install all required packages into the global Python `3.14.7` environment:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If you prefer an isolated virtual environment instead of installing globally:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS / Linux:      source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 2. Pyrefly & Ruff Configuration (`pyrefly.toml`)

Pyrefly is configured in `pyrefly.toml` to perform syntax, type, and dependency
(`missing-import`) checks across both Python files and Jupyter notebooks:

- `project-includes = ["**/*.py*", "**/*.ipynb"]`
- `project-excludes = ["**/.venv", "**/__pycache__", "**/.ipynb_checkpoints"]`
- `python-version = "3.14"`
- `python-interpreter-path` & `site-package-path`: Pre-pointed to the global
  Python `3.14.7` executable and both system and user `site-packages`
  directories.

If you are running on a different machine or OS, update
`python-interpreter-path` and `site-package-path` in `pyrefly.toml` to match
your local Python `3.14.7` paths (or pass them via CLI flags):

```bash
# Optional: install Pyrefly and Ruff CLIs if running outside VS Code
python -m pip install pyrefly ruff

# Run Ruff lint checks
ruff check .

# Run Pyrefly syntax, dependency, and type checks
pyrefly check

# Inspect resolved interpreter and site-packages paths
pyrefly dump-config
```

### 3. Dedicated IDE Configuration (`.vscode/`)

Opening this folder in **VS Code** or **Antigravity** automatically applies
the workspace settings in `.vscode/settings.json` and prompts for the
recommended extensions in `.vscode/extensions.json`:

- **Recommended Extensions:**
  - `ms-python.python` — Python support
  - `ms-python.vscode-python-envs` — Python Environments manager
  - `meta.pyrefly` — Pyrefly language server (syntax, import/dependency, and
    type checking)
  - `ms-toolsai.jupyter` — Jupyter notebook runner and renderer
  - `charliermarsh.ruff` — Ruff linting and formatting
- **Key Workspace Settings (`.vscode/settings.json`):**
  - `python.defaultInterpreterPath` & `ruff.interpreter`: Point to the global
    Python `3.14.7` executable. Update these paths if your Python `3.14.7`
    installation is located elsewhere.
  - `python-envs.defaultEnvManager`: Set to `ms-python.python:system` with
    `ms-python.python:pip` and `python.globalModuleInstallation: true` so the
    IDE connects directly to the global Python `3.14.7` environment instead of
    creating or prompting for a `.venv`.
  - `python.languageServer`: Set to `"None"` so Pylance does not duplicate or
    conflict with Pyrefly diagnostics.
  - `pyrefly.pyreflyExecutable`: Set to `"bundled"`, with
    `python.pyrefly.diagnosticMode: "workspace"`,
    `python.pyrefly.typeCheckingMode: "default"`, and
    `python.pyrefly.syncNotebooks: true` enabled for live `.ipynb` and `.py`
    checks.
  - `jupyter.excludeUserSitePackages: false` &
    `jupyter.kernels.excludePythonEnvironments`: Ensures Jupyter loads user-site
    packages and filters out unrelated local interpreters.

## First-Time Run & Verification Checklist

1. **Confirm Python 3.14.7 & Dependencies:**

   ```bash
   python --version
   python -m pip install -r requirements.txt
   ```

2. **Verify Project Integrity & Deliverables:**

   ```bash
   python -m unittest discover -s tests -v
   ```

3. **Run Ruff & Pyrefly Checks:**

   ```bash
   ruff check .
   pyrefly check
   ```

4. **Open & Run the Notebook:**
   - Open `metro-flow-ml.ipynb` in VS Code / Antigravity (select the
     **Python 3.14.7** / `Python 3` kernel in the top-right kernel picker,
     powered by `ipykernel` and `ms-toolsai.jupyter`) and click **Run All**.
   - Alternatively, if you prefer launching the standalone browser UI outside
     VS Code, install `notebook` (not bundled in `requirements.txt`) and start
     it:

     ```bash
     python -m pip install notebook
     python -m notebook metro-flow-ml.ipynb
     ```

   - Executing all cells regenerates `dataset/traffic_data_cleaned.csv`,
     `model/traffic_xgboost_model.pkl`, and `visualizations/traffic_map_view.html`.

5. **Run the FastAPI Endpoint (Optional):**
   - Set `RUN_API_SERVER = True` in the final cell of `metro-flow-ml.ipynb`,
     or send requests to `POST /api/predict-traffic` with `hour`,
     `day_of_week`, `month`, `year`, `weather_code`, `temp`, `rain_1h`,
     `snow_1h`, `clouds_all`, and `is_holiday`.

### Troubleshooting First-Time Setup

- **Missing imports in Pyrefly or notebook cells:** Confirm
  `python -m pip list` shows `xgboost`, `ipywidgets`, `fastapi`, `pydantic`,
  `uvicorn`, `numpy`, `pandas`, `matplotlib`, `seaborn`, `scikit-learn`,
  `folium`, `joblib`, `pandas-stubs`, and `types-seaborn` under the **same**
  Python `3.14.7` executable configured in `pyrefly.toml`
  (`pyrefly dump-config`) and VS Code.
- **Wrong Jupyter kernel selected:** Open the VS Code Command Palette
  (`Ctrl+Shift+P`), run **Notebook: Select Notebook Kernel**, and choose the
  global **Python 3.14.7** interpreter (`Python 3`).
- **Interactive map rendering:** If `IFrame` does not render inline in a
  restricted viewer, open `visualizations/traffic_map_view.html` directly in
  any web browser.
